# 视觉世界模型：能自己训练、能展示决策差异的升级方向

调研日期：2026-09-17。本文核验了 6 条研究主线的论文原文、作者项目页及代码仓库；抓取状态、链接、内容 SHA-256 见 [来源审计](../artifacts/research-upgrade/visual-sources.json)。这是一轮有范围的选题调研，并非穷尽文献综述。

## 结论

当前“学习一个位置相关阻尼参数”的系统，与用户期待的视觉世界模型存在明显距离。可升级为 **“看见场景 → 想象不同动作会产生的未来 → 比较后果 → 执行并纠错”** 的自训练视觉系统。建议用小型推物沙盒实现：机器人不仅移动，还会推动箱子、发生接触、受未知摩擦影响；目标是把物体送到指定区域。让用户同时看到“直接推、绕到侧面推、先轻推试探”三组模型预测，再看真实执行。

上述功能明显增强展示，但“有未来视频”“使用 GRU/RSSM”“用 MPC 选动作”都已是已有方法，不能直接称为巨大算法创新。论文可以检验更具体的问题：**对存在接触与未知物理属性的场景，显式预测接触事件/对象状态，是否比只优化像素误差更有助于选择动作？** 如果采用训练期模拟器标签，必须明确标签来源及使用位置；测试决策仍只输入规定的观测和历史。

## 核验过的相关工作

### DIAMOND：未来画面必须保留决定成败的细节

- 论文：**Diffusion for World Modeling: Visual Details Matter in Atari**，2024。[arXiv](https://arxiv.org/abs/2405.12399) · [全文](https://arxiv.org/html/2405.12399v2) · [作者代码](https://github.com/eloialonso/diamond)
- 方法：扩散模型预测动作条件下的图像，智能体在模型生成的经验中学习。论文强调被离散压缩丢失的小物体等细节，可能直接影响行为。
- 对我们有用的启发：不要仅展示模糊的未来图；模型是否预测到碰撞、接触和滑移，要有独立评估。将“候选动作—预测后果—真实后果”并列，比一条导航轨迹更能说明世界模型的作用。
- 原文算力：Atari 单次实验约 **12 GB 显存、RTX 4090 约 2.9 天**；这是完整智能体训练，不是跑一个前向预测的时间。论文的 CS:GO 实验另用了 **87 小时训练视频，381M 参数（含上采样器），RTX 4090 训练 12 天**。两组规模不可混用，更不能把前者当作笔记本 5080 的耗时保证。
- 建议：借鉴展示方式与“预测质量要影响控制”的验证逻辑。10 周毕设不以复现全部 Atari 或 CS:GO 为主线；下载权重试玩可以辅助理解，但不是自己的训练成果。

### IRIS：可理解的“图像压缩 + 序列预测 + 想象训练”结构

- 论文：**Transformers are Sample-Efficient World Models**，2022 预印本、ICLR 2023。[arXiv](https://arxiv.org/abs/2209.00588) · [全文](https://arxiv.org/html/2209.00588v2) · [作者代码](https://github.com/eloialonso/iris)
- 方法：离散自编码器把图像转为 token，自回归 Transformer 建模动作条件的未来；策略在想象轨迹上学习。
- 论文的“2 小时游戏经验”指 Atari 100k 的环境数据量，**不是 2 小时训练**。附录 G 说明实验使用 A100 40 GB，每 GPU 同时跑两个实验约 7 天，均摊约 3.5 GPU 天/实验；不能据此承诺普通笔记本一天复现。
- 建议：可借鉴分阶段训练与预测回放；首次小模型优先连续潜变量与 GRU，避免同时承担离散 token、Transformer、自回归采样与强化学习训练四类风险。

### DreamerV3 与 Dreamer 4：世界模型的强项是支持行为学习

- **Mastering Diverse Domains through World Models**，2023 预印本。[arXiv](https://arxiv.org/abs/2301.04104) · [作者仓库](https://github.com/danijar/dreamerv3)
- DreamerV3 从经历中学习世界模型，并在潜空间想象中训练 actor/critic。重点是模型支持了行为改善，而不是图像是否好看。
- 当前作者 README 的代码要求 Python 3.11+，明确测试于 Linux/Mac，使用 JAX；本项目当前是 Windows/Python 3.10/PyTorch。直接替换技术栈有额外工程成本。可借鉴 RSSM 思想，实现独立小型 PyTorch 版本，但应称为“受 Dreamer 启发的模型”，不能暗示完整复现。
- **Training Agents Inside of Scalable World Models**，2025，即 Dreamer 4。[arXiv](https://arxiv.org/abs/2509.24527) · [全文](https://arxiv.org/html/2509.24527v1) · [作者项目](https://danijar.com/project/dreamer4/)
- Dreamer 4 使用视频世界模型和想象训练，在离线 Minecraft 数据条件下学习复杂任务。论文原文给出 **2B 参数（400M tokenizer + 1.6B dynamics）、256–1024 TPU-v5p**，主要使用 2541 小时 VPT 数据。
- “单 GPU 实时交互”是推理能力，不能解释为单 GPU 可以低成本从头训练该规模模型。它是发展方向和视觉展示参考，不是本项目的复现目标。

### DINO-WM：更贴近可验证的机器人任务

- 论文：**DINO-WM: World Models on Pre-trained Visual Features enable Zero-shot Planning**，2024 预印本，核验版本修订于 2025-02。[arXiv](https://arxiv.org/abs/2411.04983) · [全文](https://arxiv.org/html/2411.04983v2) · [作者代码](https://github.com/gaoyuezhou/dino_wm)
- 方法：使用预训练 DINOv2 空间 patch 特征；从离线动作轨迹学习未来特征，给定目标图像后优化动作序列。覆盖迷宫、PushT、不同形状推物、绳索与粒子等任务。
- 与本项目最相关：由“去一个坐标”升级为“把物体变成目标图像里的样子”。重建像素可以作为可视化分支，规划不必依赖像素级误差。
- 原文附录 A.8 的示例：A6000 上单步批量 32 推理约 0.014 秒；CEM 100 候选 × 10 次迭代的完整规划约 53 秒。**单次神经网络推理快不等于整个规划实时**。
- 官方 `conf/train.yaml` 使用单 H100 的集群资源配置、224px、batch 32、100 epochs。这是公开配置，不是经过本机测量的最低硬件需求或耗时。冻结预训练编码器 + 自己训练动态预测器可作为第二条路线；必须明确哪些权重来自别人，哪些在本项目训练。

### V-JEPA 2 / 2.1：前沿参照，不能把预训练算力隐藏掉

- 论文：**V-JEPA 2: Self-Supervised Video Models Enable Understanding, Prediction and Planning**，2025。[arXiv](https://arxiv.org/abs/2506.09985) · [作者代码](https://github.com/facebookresearch/vjepa2)
- 原文摘要：先用 **超过 100 万小时互联网视频**进行动作无关预训练，再用 **少于 62 小时 DROID 机器人视频**后训练动作条件模型。这不是仅用 62 小时视频从头完成整个训练。
- 官方 action-conditioned 配置基于 ViT-g，`nodes: 4`、`tasks_per_node: 8`；这些是公开分布式训练设置，不是 16 GB 笔记本复现承诺。作者 README 列出的 V-JEPA 2 编码器规模为 300M / 600M / 1B。
- 当前作者 README 新增 **2026-03-16 的 V-JEPA 2.1 发布记录**，提供密集、时间一致特征的新训练路线与 80M 到 2B 权重。但其 README 的 2.1 论文链接仍为 `arxiv.org/abs/TODO`，所以本调研只确认官方代码/发布记录存在，不编造 2.1 论文编号或评测结论。
- 启发：潜空间预测可以比生成漂亮视频更适合规划。用已有编码器时，毕设贡献应落在动态模型、任务设计和验证，不应把基础模型能力算成自己的训练成果。

## 三种升级选择

| 路线 | 用户能直接看到什么 | 自己训练什么 | 主要风险 | 本项目建议 |
|---|---|---|---|---|
| 小型接触推物世界模型 | 一次动作产生多个未来；有的撞偏、有的送达；执行结果与预测同步对比 | 64×64 图像编码器、动作条件循环动态模型、解码器；可加接触预测头 | 长期误差、规划利用模型漏洞、碰撞后图像模糊 | 优先：任务清楚、数据可控、训练可以缩小 |
| 冻结视觉特征 + 目标图像规划 | 指定一张目标图，让机器人推到对应布局 | 冻结特征上的动作动态模型；可选可视化解码器 | 预训练域差异、特征距离未必等于任务距离、CEM耗时 | 对照路线：先验证特征是否保留小物体位置 |
| 可交互神经小游戏引擎 | 按方向键后，未来画面完全由模型生成 | 自建小游戏上的动作条件视频模型 | 好看但物理规则不稳；仅生成不一定有行为贡献 | 可做展示副线，不宜同时承担完整RL主线 |

## 推荐的可检验研究设计

暂拟题目：**《面向接触交互任务的动作条件视觉世界模型与反事实规划研究》**。题目中的“反事实”指从同一个观测历史分别输入不同候选动作，比较模型预测后果；并不因此自动构成新的因果识别方法。

第一版只包含一个机器人、一个可推动刚体、围栏和目标区。变化因素逐步加入物体初始姿态、质量/摩擦和局部遮挡。先建立可学习的单一任务，再考虑门机关或多物体连锁反应，避免把 10 周都花在沙盒规则上。

**自训练结构（工程方案，尚未实现/测量）：** 64×64 RGB → 小 CNN/VAE → 带动作输入的 GRU/RSSM → 多步潜状态、图像重建、接触事件预测。历史窗口用于推断速度与未知物理属性。首先训练预测器并用短视野 CEM/MPC 选动作；只有闭环预测规划已经稳定，才考虑在想象空间训练策略。

**可验证的改进候选：** 在统一骨干、数据和训练预算下，对比纯图像重建损失与“重建 + 对象运动/接触一致性”辅助损失。辅助标签若来自训练模拟器，应公开标签数量和生成规则。还应加入“同样标签训练直接策略”的对照，判断收益是否只是额外监督，而不是世界模型本身。只有结果支持时才写为改进贡献；对象辅助学习本身不是未经检索即可宣称原创的点。

**对比应同时覆盖四个层面：**

1. 同一真实初始状态、同一动作序列：画面预测、物体位置、接触时刻、目标覆盖率的误差，避免仅报 PSNR。
2. 同一初始布局、各自决策：反应式/行为克隆策略、冻结物理规划、在线辨识物理规划、学习世界模型规划；可访问真实动力学的规划器只作上界，并标明特权信息。
3. 模型消融：去动作输入、去历史记忆、去接触辅助损失、短/长想象视野。在未见过的布局和物理参数上检验是否真的学到动作后果。
4. 资源公平：同训练轨迹与数据划分、训练随机种子、候选数/模型调用预算和实际决策延迟。若策略使用额外在线交互，单独报告交互预算。

展示中的“精彩失败例”可以帮助理解，但报告必须覆盖预先固定的完整测试集。复杂任务也不保证学习模型超过正确的物理模型；若两者同样知道真实动力学，不能预设学习模型必胜。

## 今天能启动的验证，而非未经测量的耗时承诺

先做低分辨率数据与预测闭环：固定训练/验证/测试地图和物理参数划分，采集随机动作加少量覆盖策略的接触片段，训练一个小动作条件循环模型。把时间投入记录为日志，先在本机测量吞吐、峰值显存和学习曲线，再决定完整数据量和训练时长。

验收看三件事：模型预测是否胜过“最后一帧不变/匀速外推”；改变动作是否改变正确的运动后果；短视野规划是否能在固定测试集上完成推物任务。如果只会重建背景、动作不起作用，或规划频繁利用模型漏洞，优先修复数据/目标函数，不加大模型掩盖问题。

本轮不承诺“巨大创新差异”，但这条路线能让系统从参数拟合演示推进到**可自己训练、可看见未来、可验证决策收益**的世界模型毕业设计。
