# 「预见 · Foresight Lab」演示故事板

状态：设计草案。下面描述的是计划中的答辩演示，不是当前已实现功能，也不预设算法一定优于基线。

## 一句话记住这个作品

“这个智能体会先在学到的世界模型里尝试几个未来，再选择现在要做的一步。”

推荐以“移动机器人穿过有移动障碍的实验场”为场景。二维俯视图已经能够清晰表达行为，不必先做复杂三维场景。

## 三分钟流程

| 时间 | 操作与画面 | 要讲清楚的科学问题 |
| --- | --- | --- |
| 0:00–0:25 | 暂停场景，标出机器人、目标、障碍，显示过去几步轨迹 | 智能体有哪些输入、需要完成什么任务 |
| 0:25–0:55 | 从同一状态给出几个候选动作，逐帧显示模型预测的不同未来 | 世界模型确实以动作为条件；不同动作会产生不同结果 |
| 0:55–1:25 | 选择一条预测轨迹，执行第一步，再把真实位置叠在预测之上 | 闭环规划与预测误差，避免只展示漂亮动画 |
| 1:25–2:05 | 在预先定义的范围内改变运动阻尼；用同一测试种子回放各算法 | 模型会遇到什么变化，不确定性与真实误差是否对应 |
| 2:05–2:35 | 展示固定视野与自适应视野在计算预算约束下的行为 | 往前看更远有收益也有误差，适应机制是否值得使用 |
| 2:35–3:00 | 展示完整测试集统计和一个失败片段 | 单段演示不能证明改进，适用边界同样是研究结果 |

若最终结果显示自适应方法在某些场景更差，保留对照并解释原因。演示可以选择便于理解的案例，但必须标出它是案例，不能替代整体评测。

## 界面布局建议

- **左侧主画面：实际环境。** 机器人、目标、动态障碍、已经执行的轨迹。
- **右侧主画面：预测未来。** 与左侧同一坐标系，显示候选动作轨迹；选中轨迹使用粗实线，其余使用细虚线。
- **底部时间轴：预测与现实对照。** 支持回放、逐步前进和查看某一决策时刻的状态。
- **少量状态信息：** 当前方法、预测步数、候选数、决策延迟、模型分歧指标。完成多种子测试后才加入统计图。

颜色之外还要用线型、标签或形状区分预测、实际与不同方法。优先保证投影上能看清，不在画面里堆满曲线和数字。

## 真正值得做的交互

1. **如果换一个动作，会怎样？** 在同一初始状态与环境设定下比较动作条件预测。这里称“假设动作比较”，不据此宣称具备因果识别能力。
2. **模型在哪些地方不确定？** 画出集成成员的预测轨迹或分歧带。未经覆盖率校准，不把它标成“95% 置信区间”。
3. **现在该看多远？** 显示本次视野调整和相应计算预算，同时展示固定视野方法。
4. **预测到底准不准？** 切换到真实日志中的误差叠加；不利用真实未来修正此前已经显示的预测。

“临时改变环境参数”和“自由拖动障碍”不是同一个实验：前者可用于主论文的受控动力学变化，后者可作为额外交互体验。若支持自由编辑，需标成演示场景，不混入标准测试结果。

## 展示输出的真实性要求

| 显示内容 | 应来自哪里 |
| --- | --- |
| 未来轨迹 | 冻结世界模型基于当前信息的 rollout |
| 已执行轨迹 | 独立仿真器实际产生的状态 |
| 不确定性 | 明确定义的集成分歧或预测分布指标 |
| 决策解释 | 规划器实际记录的代价项、约束和选择结果 |
| 成功率、碰撞率、延迟 | 冻结测试集的原始日志与统计脚本 |

第一版用结构化事实解释，例如“候选 3 的碰撞代价较低；本步规划视野为 8”。自然语言可以用模板生成，无需额外接入大语言模型。

## 建议的实现顺序

先让环境、模型与规划器通过标准日志工作，再做回放界面，最后接入实时交互。优先实现 Python 生成结果 + 浏览器回放，实时服务和复杂前端可以后置。演示名称、配色和布局都是可替换设计，不影响论文的方法与实验。

答辩前准备一个无需联网即可播放的真实实验回放，记录对应配置、模型版本和运行种子；现场实时运行与预录回放应明确区分。
